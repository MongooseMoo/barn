1. **The ownership graph is internally consistent and leaves one source-to-bytecode boundary.** The pipeline places `compiler` around the MOO parser and bytecode compiler, assigns `parser` the source-to-`verb.Program` step, assigns `bytecode` only IR-to-bytecode lowering, and gives task, scheduler, and VM only compiled programs (`prompts/spec-draft-verb-language-ownership.md:16-28`). 2. **Original database verb source, semantic IR, compiled programs, and queued-task source are kept distinct.** The draft defines original source as the exact persisted lines used by `verb_code()` and database verb-program writing, excludes textual trivia from `verb.Program`, and says canonical formatting never replaces stored source (`prompts/spec-draft-verb-language-ownership.md:30-45`). It separately requires queued-task `code` to remain an IO artifact compiled once during restoration rather than syntax or IR owned by live task/scheduler state (`prompts/spec-draft-verb-language-ownership.md:47-50`, `prompts/spec-draft-verb-language-ownership.md:121-127`). Those rules preserve both database contracts: verb code remains line-oriented source terminated by `.`, while queued tasks retain their own `code...` block (`spec/database.md:173-185`, `spec/database.md:189-222`). They also agree with the plan's original-source and restoration invariants (`plans/multilingual-verb-language-cleanup-plan.md:76-93`, `plans/multilingual-verb-language-cleanup-plan.md:271-278`).

The try/finally requirement preserves the language semantics from Section 10 while assigning enforcement to compiled handler/control flow instead of recursive statement execution (`prompts/spec-draft-verb-language-ownership.md:156-162`; `spec/statements.md:558-610`). The parser charter repeats the direct-construction and deletion-first convergence rules and forbids compatibility wrappers or helpers (`prompts/spec-draft-verb-language-ownership.md:174-204`), satisfying the plan's forbidden-final-surface rules (`plans/multilingual-verb-language-cleanup-plan.md:95-110`).
