## Source facts
- SIGALRM calls `requestCheckpoint` directly (`server/signals_unix.go:41-42`). `checkpointChan` is buffered 1 (`server/server.go:112`) and the send is non-blocking (`server.go:433-436`): with one checkpoint running and one queued, a further SIGALRM is silently dropped. The harness therefore sends one SIGALRM at a time, only after it has seen `checkpoint complete` or `checkpoint failed` for the previous one.
- Checkpoint flow `server.go:469-495`: log `checkpoint started`, `#0:checkpoint_started`, `dumpCheckpoint`, `#0:checkpoint_finished(true)`, log `checkpoint complete` (`duration_ms`). Failure logs `checkpoint failed` (`server.go:396`).
- `dumpCheckpoint` (`server.go:499-535`): running mode captures under `WithCheckpointBarrier`, then Serialize and Publish outside it. The ordinary binary logs nothing between start and completion, so the stage at a kill is observable only through files: `P.tmp` (created at BeginCheckpoint, `db/format/checkpoint_stage.go:53`), `P.tmp.waifids` (Publish, `:135`), `P.new.recovery-*` and the journal `P.new.publication` (`checkpoint_publication.go:198,237`), the two renames (`:370-372`), journal and recovery-dir removal (`:285-296`).
- Output names for `--db P`: `P.new`, `P.new.waifids`, temp `P.tmp` (`checkpoint_stage.go:33-35`). The journal's recovery directory must start with `basename(P.new)+".recovery-"` (`checkpoint_publication.go:270-271`), so the artifact set keeps its basenames and is recovered in place.
- `LoadDatabase(path)` recovers `path.publication` before reading (`db/format/reader.go:157-166`).
- The profile manifest's `database_checksum` is computed at `internal/app/app.go:352` (BuildManifest, `profile/manifest.go:62`), before `srv.LoadDatabase` at `app.go:388` where recovery runs (`reader.go:163`). So the manifest always names the pre-recovery file. Resolution approved by team-lead: manifest checksum must equal the pre-launch hash; the database+sidecar pair hashed after readiness must be a pair the frozen journal/stage permits (journal Next, Previous, or the unchanged input). Barn never writes its input path after load. Plan section 2 para 4 is corrected in this PR.
- Barn dispatches restored tasks as soon as `InputProcessor` starts, before `server_started` (`reports/jepsen-toast-task-semantics.md:192-204` in the main checkout). Choice for this lane: no workload task persists (each transaction is one eval task with no fork/suspend/read); the recovery observation also reads `queued_tasks()` and any task beyond the fixture's initial ones is a finding.

## Decisions and why
- Recover in place: the restart input is the interrupted generation's actual `P.new` with its journal, recovery directory and sidecar untouched; a forensic copy is taken first. Only when neither `P.new` nor its journal exists is the unchanged input pair used, recorded as `no-checkpoint-output`.
- Stage is classified from the frozen files while the owned process is SIGSTOPped (state T verified), then SIGKILL. Requested timing is recorded separately and never credited as a stage.
- PR B (#744) gives every generation fresh row objects (`ROWS_CODE`) and resets `#0.jepsen_rows`, so rows are per generation, not cumulative. Bound to that: admission also writes `#0.jepsen_epoch = g` (after the rows exist; no checkpoint can run inside `launch`, which holds the lifecycle lock, and the interval is 0). Before admitting a recovered generation, one task reads the epoch marker, `length(queued_tasks())` and, when the marker names the crashed generation p, every row p touched through p's layout. Marker == p: the cut includes p's admission, S0 for p's rows is empty, D = R. Marker != p: the cut predates p's admission, D is empty and the only permitted cut is p's launch pair. This replaces "keep rows cumulative" from the Phase 1 design.
- Recovery observation R is taken before admission and before clients are live (the adapter's `live` is None during launch), and no workload task can persist; the task count must equal the count at p's own pre-admission observation.
- The no-output case copies the unchanged input pair into the new generation (no recovery happens, so the fresh launch is identical); the output case launches in place on `P.new`.

## Surprises
- Barn cannot start with `--profile-manifest` on a database path that does not exist yet: BuildManifest hashes `--db` (`internal/app/app.go:352`) before LoadDatabase (`app.go:388`) would restore a first publication's saved next pair. So a stop in the `journal-published` stage of a generation's FIRST publication (no previous `P.new`) cannot be restarted through the managed lifecycle; `OwnedBarnServer.start` refuses it with that reason. The live lane always completes a live checkpoint before each checkpoint-crash, so F is never a first publication there. Not changed in Barn (out of scope); reported to team-lead.

- First CI campaign (run 42956762397) was red from a harness defect: `wait_checkpoint` used the exited-process log read, which rejects any growth during the read, while Barn was still appending (`gen-006/server.log`: `checkpoint started` 21:08:01.695, `checkpoint complete` duration_ms=8 at .704; failure recorded 0.2 ms after SIGALRM, lifecycle.jsonl:75-76). Fixed: live reads require the same inode and no truncation, stop at the pre-read size and use complete lines only; the final-checkpoint read stays strict. Elle verdicts for generations 0-6 were all true in that run.

## Snapshot oracle (as implemented, `snapshot_checks`)
Per checkpoint-crash of generation p: candidate cuts are the unchanged input (p's launch pair), the last completed live checkpoint A of p, and every pair the frozen files identify as F (journal next, staged temp pair with sidecar, recovery-dir next, a published output that is not A). Recovered pair must equal `expected_recovery(frozen artifacts)` (else recovery-failure) and match some candidate (else recovery-failure "matches no permitted cut"). Cut-independent (correctness): repeated or never-sent token, all-or-none writes per transaction (native errors excluded), an included ok transaction's reads present, every ok read and final observation prefix-comparable with R. Per cut (accept if any cut fits): unchanged input needs D empty and the starting epoch marker; A/F need marker == p, every ok write completed before the cut's SIGALRM present, and for A no write first sent after A's acknowledgment. Queued task count must equal p's own launch count (else incomplete). Journal times: send recorded before sending, completion after the reply, so both bounds are sound.
